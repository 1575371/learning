# 技术说明

这份文档解释 demo 内部怎么算的：坐标系、双耳线索公式、两条合成模型的细节、自由路径的样条算法，
以及三维视图的投影与交互实现。写给想改代码或想弄清「这个数字是怎么来的」的人。

---

## 一、坐标系统

右手坐标系，与 Web Audio 的 `AudioListener` 完全一致：

```
        -Z （正前方）
             ↑
  -X ← 听者 → +X        Y 轴向上（离地高度）
             ↓
        +Z （正后方）
```

| 量 | 值 | 说明 |
|---|---|---|
| 听者位置 | `(0, EAR_H, 0)` | `EAR_H = 1.55 m`，站立时的耳平面高度 |
| 房间 | 9.2 × 9.2 × 3.2 m | `ROOM_HALF = 4.6`、`ROOM_H = 3.2` |
| 声源高度范围 | 0 – 3.2 m | 0 = 地面 |
| 头半径 | 8.75 cm | `HEAD_R`，用于 ITD |
| 声速 | 343 m/s | 20 ℃ 空气 |

所有的角度、距离都以**双耳**为原点计算，所以听觉上的「距离」是斜距，不是地面投影距离：

```
d = |(x, y - EAR_H, z)|
方位角 = atan2(x, -(z))          // 0° = 正前，+ = 右
仰角   = asin((y - EAR_H) / d)   // + = 在耳朵上方
```

## 二、双耳线索模型

`spatial.js` 的 `binauralOf()` 把三维位置换算成四个量：ITD、ILD、两耳增益、两耳低通截止频率。
四个量都会送到音频图，同时显示在界面上。

### 1. ITD（双耳时间差）

Woodworth 球头近似：

```
τ = (a / c) · (θ + sin θ)
```

- `a = 0.0875 m`（头半径），`c = 343 m/s`
- **θ 是「侧向角」而不是方位角**：`θ = asin(|x| / √(x²+z²))`，取值 0–90°。
  代入方位角的话，正后方的声源会得到 180°，ITD 反而超过物理上限（实测过 732 µs 的错误值）
- 侧向 90° 时 `τ = 0.0875/343 × (π/2 + 1) ≈ 656 µs`，与实测数据的量级一致；
  正前与正后方都在正中面上，ITD 为 0
- 仰角会削弱侧向线索，乘一个 `cos(0.8·|仰角|)` 的经验因子
- 右耳在前的声源把延时加在**左**声道上

### 2. ILD（双耳声级差）

```
ILD = 9 · sin(方位角) · cos(0.8·|仰角|)     // 单位 dB，右正左负
gL  = 10^(-ILD/2 / 20)
gR  = 10^(+ILD/2 / 20)
```

侧向最大 9 dB，按 ±ILD/2 分给两耳，这样总功率大致不变——切换声源左右时不会觉得「变响了」。

> 注意符号：这里必须用带符号的 `sin(方位角)`。早期版本误用了 `sin(|方位角|)`，
> 结果左侧声源会被镜像成「右耳更响」，左右完全反了。

### 3. 头部遮蔽（远耳低通）

高频绕不过头部，所以远耳收到的是被压暗的声音：

```
截止频率 = 18000 · exp(-2.5 · sin θ)      // 钳在 1100 – 18000 Hz
```

再叠加空气吸收（距离越远高频衰减越多）：

```
空气截止 = 18000 / (1 + 0.22·d)           // 钳在 2600 – 18000 Hz
```

两耳各取两者的较小值。这就是「模型」模式里两个 `BiquadFilterNode` 的频率。

### 4. 空气吸收（距离的高频线索）

真实空气对高频的衰减随距离近似指数增长，所以远处的声音先失去"空气感"和齿音，
而不是整体变小声。这个线索比音量可靠得多——音量会被声源本身的响度混淆，音色不会。

```
dd   = max(0, d - 0.8)                      // 1 m 内不衰减
截止 = 20000 · exp(-0.17 · dd · absorb)      // 钳在 1500 – 20000 Hz
高架 = min(1.8 · dd · absorb, 14)            // 3.2 kHz 以上整体下压，单位 dB
```

两级串联：**低通**负责"顶端被切掉"，**高架**负责"整个高频变暗"。只做低通会显得发闷，
只做高架又切不干净，两级一起才像真实的空气吸收。

- 低通的 Q 取 **0.4**（不是默认的 1）。Q 高会在截止频率附近隆起一个尖峰，
  那正是"刺耳"的来源；Q<0.5 的斜缓过渡听感自然。
- 高架**只减不加**（gain ≤ 0），近处不 boost，避免高频过冲。
- 参数 `absorb`（界面「空气吸收」0–200%）直接缩放这两条曲线：0 时完全旁路，
  用来和第 5 小节的反射做对照实验。

实测（白噪类声源，1 m vs 6.4 m，4–16 kHz 相对 0–2 kHz 的落差）：
`absorb = 0` 时 **0.7 dB**（等于没有距离线索）、`absorb = 1` 时 **11.2 dB**、
`absorb = 2` 时 **21.1 dB**。

### 5. 一次反射（镜像声源法）

单靠直达声做不出"房间感"，但混响加太多又会厚。折中办法是**只算一次镜面反射**，
而且让它带真实方向。

把声源对**最近的那面墙**做镜像得到虚声源 S'：

```
反射路径  |S' - L|                        L = 双耳位置
路径差    Δ = |S' - L| - |S - L|
延迟      Δt = Δ / c                      （钳在 3.5 – 140 ms）
入射方向  = S' 的方向
```

- 延迟不是随便给的常数，而是由房间尺寸和声源位置算出来的：声源离墙越远、房间越大，延迟越长。
- 反射声用一个独立的 `PannerNode` 放在 S' 上，所以它真的从另一侧过来，
  而不是简单地把直达声复制一份。
- 反射要过一道低通（界面「墙面吸声」0–100%，16 kHz → 3 kHz），模拟墙面和空气对高频的额外损耗。
- **延迟下限 3.5 ms**：贴着墙的声源几何延迟可能不到 1 ms，那样会与直达声形成间距很密的
  梳状滤波器，听起来空洞、发金属声。真实房间有这种边界干涉，但对这个演示不值得，
  宁可当成小房间处理。

### 6. 直达/反射比（D/R）

这是判断远近最有效的一个量。做法是让**反射的衰减比直达慢**：

```
直达  1 / (1 + 0.5·max(0, d-1))              按 1/r 掉
反射  refLevel · 0.30 / (1 + 0.04·path)      几乎不随距离掉
```

于是距离越远，反射相对越突出：

| 位置 | 距离 | 反射路径 | 延迟 | D/R |
|---|---|---|---|---|
| 正前 1 m | 1.00 m | 8.2 m | 21.0 ms | **−14.9 dB** |
| 正前 3 m | 3.00 m | 6.2 m | 9.3 ms | **−8.3 dB** |
| 房间远角 | 6.22 m | 6.5 m | 3.5 ms* | **−3.3 dB** |

\* 远角贴着墙，几何延迟只有 0.8 ms，被下限抬到 3.5 ms。

从 1 m 到远角，D/R 变化 **11.6 dB**——这就是"听起来变远了"的主要依据，配合第 4 节的
高频衰减，两个线索方向一致、互相加强。

`refLevel`（界面「一次反射 强度」0–150%）整体缩放反射增益；设为 0 就是纯直达声，
可以用来做 AB 对照。

### 7. 为什么不会"混响过厚"

- 每条声源只有**一次**反射，不是一串早期反射；剩下的交给总线的扩散混响。
- 总线混响的脉冲响应里**去掉了离散早期反射抽头**（原来有 5 个）。早期反射现在由每条声源
  自己的镜像支路提供，如果总线再放一遍就是重复计入，听感上就是"糊"和"厚"。
- 反射本身经过低通，能量集中在 3 kHz 以下，不会叠出明亮的金属尾音。

## 三、声音

### 0. 犬吠与脚步：真实录音（当前默认）

这两类声音**不再合成**，直接用实录：

| 项 | 犬吠 | 脚步 |
|---|---|---|
| 原始素材 | `assets/audio/dog_barking.mp3` | `assets/audio/footsteps.mp3` |
| 时长 / 内容 | 1.62 s，两声 | 5.25 s，八步（含一次自然停顿） |
| 采样率 / 声道 | 48 kHz 立体声（相关性 0.97，近似单声道） | 48 kHz，左右完全一致 |
| 峰值 / RMS | 0.893 / 0.113 | 0.881 / 0.018 |
| 底噪 | −54 dB | −40 dB（室内底噪） |

**为什么要 base64 内嵌**：项目要求双击 `index.html` 直接运行，而 `file://` 下 `fetch()` 本地文件会被
CORS 拦死。把 MP3 塞进 `assets/js/samples.js` 变成 `data:audio/mpeg;base64,...`，
`fetch(dataURI)` + `decodeAudioData()` 在任何协议下都能工作。

**解码时机**：页面 `boot()` 时就启动 `loadSamples()`（不需要用户手势），
用户点「开始试听」时通常已解码完成；`startAudio()` 里再 `await` 一次兜底，失败则回退到合成。

**犬吠如何拼成循环**（`buildBarkLoop()`，因为原素材只有两声、太短）：

```
组 1  原速      间隔 0.00 s
组 2  −3.0% 变速  间隔 0.35 s   音量 0.94
组 3  +2.8% 变速  间隔 0.90 s   音量 0.97
```

变速用的是线性插值重采样（`pitchShift()`），所以音高和时长一起变——听起来像同一只狗不同力度的吠叫。
拼出来 6.37 s，六声吠叫的时间点是 0.04 / 0.86 / 2.02 / 2.86 / 4.59 / 5.39 s：
组内间隔 0.82 s，组间 1.16 s 与 1.73 s，回卷间隔 1.02 s，形成不规则但自然的节奏。
拼接处做过跳变检查，最大一阶差分出现在吠叫自身起音（0.08 s 处），说明接缝没有咔哒声。

**脚步**直接循环：八步间隔 0.59 s，末尾到开头的空档也是 0.59 s，接缝处节奏连续。

### 1. 犬吠与脚步的合成版（回退）

`samples.js` 缺失或解码失败时，引擎会退回 `synth.js` 的合成实现。它用**声源—滤波器**结构，
比录音差一档，但能保证页面照常出声。下面 1.1–1.3 小节描述的就是这个版本，保留它是为了可维护性。

#### 1.1 二阶共振器（`resonator`）

模拟声道的一个共振峰，Klatt 式两极点：

```
y[n] = A·x[n] + B·y[n-1] + C·y[n-2]
B = 2r·cos(2πf/fs),  C = -r²,  r = exp(-π·BW/fs)
A = |1 - B·e^{-jθ} - C·e^{-2jθ}|        // 让峰值增益恰为 1
```

关键在 `A` 的取法：按峰值归一，而不是按直流归一。这样不同带宽的共振峰之间不会互相压制——
早期版本用 `A = 1 - r`，宽带共振峰（2–4 kHz）被压掉了 20 dB，整只狗叫听起来像电子音。

#### 1.2 狗叫（`SYNTH.bark`）

一只中型犬的连续短吠：4.9 s 里两组，每组三声，组内间隔 0.30–0.35 s。
每声长 0.15–0.19 s——这是「汪」而不是「嗷」的关键，超过 0.3 s 就会听成拖长音。

每次发声的内部：

| 环节 | 做法 |
|---|---|
| 声门源 | Rosenberg 脉冲（`tp = 0.46`, `tn = 0.16`）取一阶差分，得到类似声门流的激励 |
| 基频 | 以 376–424 Hz 起音，`1 - exp(-6.5u)` 在 40% 内滑落到起音的 46–56%（约 180–230 Hz） |
| 抖动 | 周期抖动 3.4%、幅度抖动 7%，每 32 个样点更新一次；另有 47 Hz、1% 的轻微粗糙调制 |
| 共振峰 | 走一遍「w → ɑ → o」的口型：F1 300 → 880 → 400，F2 860 → 1520 → 880，F3 2350–2700，再加 3.9 kHz 的第四共振峰 |
| 带宽 | F1 118 Hz、F2 175 Hz、F3 250 Hz（偏宽，避免共振峰"啸叫"成电子音） |
| 送气噪声 | 起音 4 ms 内 0.30 的爆破，中段降到 0.095 保持音高清晰，末尾再抬到 0.38（收口的气声） |
| 高频气声 | 噪声经一阶高通（约 570 Hz）单走一条干路，增益 0.22，给「汪」一点边缘 |
| 唇辐射 + 过载 | 一阶差分 +6 dB/oct，再 `tanh(1.5y)` 轻度饱和 |
| 包络 | 4 ms 起音 → 保持 → 62% 处降到 0.66 → 86% 处 0.26 → 末端归零 |

**每次吠叫都独立随机**：基频 ±4.5%、共振峰整体缩放 ±4%、带宽 ±13%、时长 ±15%。
这是去掉"机械感"最有效的一步——同一段波形重复六次，耳朵立刻听出是采样循环。

实测（48 kHz）：每声的周期性（自相关峰值）r = 0.66–0.82，即明显是**有声**的吠叫而不是噪声；
频段相对总 RMS 为 400–900 Hz −2 dB、900–2000 Hz −5 dB、2000–4000 Hz −9 dB、4 kHz 以上 ≤ −13 dB。

#### 1.3 脚步（`SYNTH.steps`）

一步 = 三层叠加，每层都由同一条极短的冲击噪声整形而来：

```
raw(t) = noise · min(1, t/0.9ms) · exp(-85t)

body = lowpass(raw, 430–540 Hz, Q 0.7)     × 0.72    // 地板与鞋体的"闷底"
mid  = bandpass(raw, 640–810 Hz, Q 1.0)    × 3.2     // 主要的"笃"
tap  = bandpass(raw, 1750–2500 Hz, Q 0.85) × 0.85    // 鞋跟落地的那一下"嗒"
```

再叠加三点：

- 地板共振：`sin(2π·f·t)·exp(-95t)`，f 在 150–205 Hz 随机（每步不同），30 ms 内衰完
- 鞋底细碎摩擦：只在头 30 ms，`exp(-75t)` 的高频噪声，增益 0.045
- 前掌二次落地：42 ms 后的轻击，0.9 倍共振频率 + 一小段噪声

节奏：步频 0.52 s、抖动 ±3%，左右脚力度差 6%；整段 7.0 s 共 13 步。

实测：步间隔 0.51–0.535 s（平均 0.523 s）；单步在 25 ms 内衰到阈值的 25% 以下，波峰因数 11.3
（冲击型声音的典型值）；频段为 0–150 Hz −10 dB、150–400 Hz −8 dB、400–900 Hz −6 dB、
900–2000 Hz −5 dB、2000–4000 Hz −6 dB，即"中频敲击为主 + 高频一点点接触声"，不是低频轰隆。

## 四、自由路径

`traj = { type:'path', pts:[{x,y,z}...], closed, period }`

### 1. 样条插值

控制点之间用均匀 Catmull-Rom（`spatial.js` 的 `catmull()`）：

```
P(t) = ½·[ 2P₁ + (-P₀+P₂)t + (2P₀-5P₁+4P₂-P₃)t² + (-P₀+3P₁-3P₂+P₃)t³ ]
```

每个控制点都是曲线上的点（插值型，不是逼近型），所以拖动哪个点，曲线就穿过哪个点——
不会出现「拖了没反应」的困惑。开放路径的两端用端点自身顶替缺失的邻点，避免曲线甩出去。

### 2. 匀速行走

样条按参数 `t` 均匀取样时，弧长并不均匀（拐弯处更慢）。所以：

1. 每段细分 20 个点，得到一条密集折线
2. 累加相邻点距离，得到累积弧长表 `cum[]`
3. 播放时按「已走过的距离」而不是参数去查表，二分定位区间后线性插值

这样不管控制点疏密、曲率大小，声源都是匀速走完的。

### 3. 走法

- `closed = true`：环形，`u = (t/period) % 1`
- `closed = false`：来回走，`u = u<0.5 ? 2u : 2-2u`（三角波）

结果按 `pts` 的内容做缓存（`_key`），改了点才重算。

## 五、三维视图

### 1. 相机

```
eye = pivot + dist · (sin(yaw)·cos(pitch), sin(pitch), cos(yaw)·cos(pitch))
forward = normalize(pivot - eye)
right   = normalize((-forward.z, 0, forward.x))     // × up(0,1,0)
up'     = right × forward
```

`pitch = 0` 是水平视线，`pitch = π/2` 是正上方俯视。默认 `yaw 0.58 / pitch 0.50`，
即从听者的右后方、约 29° 俯角看过去——正前方（-Z）落在画面里偏上的位置。

### 2. 投影与反投影

```
z_c = (p - eye)·forward                  // 深度，≤ 0.25 直接丢弃
x_c = (p - eye)·right
y_c = (p - eye)·up'
screen = (VW/2 + x_c/z_c · focal,  VH/2 - y_c/z_c · focal)
focal = (VH/2) / tan(fov/2)              // fov = 48°
```

反投影用于拖拽：把屏幕点变成射线，与「当前声源所在高度的水平面」求交：

```
dir  = normalize(right·x' + up'·y' + forward)
t    = (planeY - eye.y) / dir.y
hit  = eye + dir·t
```

所以拖一个 1.9 m 高的声源时，鼠标划过的是 1.9 m 高的那个平面，而不是地面——视觉上「抓着它走」。

### 3. 绘制顺序

1. 地面（填充 + 1 m 网格 + 中轴）
2. 四面墙（自地面向上渐隐的填充 + 每米的竖线与横线）
3. 距离环、方位提示
4. 轨迹（线 / 环 / 样条曲线）与控制点
5. 声源与听者：按相机深度从远到近排序后依次画（画家算法）
6. 标签层：统一做矩形避让，位移较大时画引线回指

### 4. 拖拽交互一览

| 命中对象 | 左键拖动 | Shift + 拖动 |
|---|---|---|
| 声源 | 水平面移动（整体平移轨迹） | 改高度 |
| 轨迹控制点（A / B / 路径节点） | 水平面移动该点 | 改该点高度 |
| 空白 | 旋转视角 | 同左 |

双击路径节点删除；滚轮改 `dist`；命中测试的半径是 12 px（控制点）/ 22 px（声源），
且只对未静音的声源生效。

## 六、音频图

```
每个声源：
  BufferSource ──▶ vol ──▶ Lowpass ──▶ HighShelf ──┬─▶ tapMono ────────────────────▶ bus
        （距离滤波：空气吸收，五种模式共用）        ├─▶ Panner(equalpower) ▶ tapSt ──▶ bus
                                                    ├─▶ Panner(HRTF)       ▶ tapHr ──▶ bus
                                                    ├─▶ gL/gR ▶ Delay ▶ Lowpass ▶ Merger ▶ tapMd ▶ bus
                                                    ├─▶ Delay ▶ Lowpass ▶ Gain ─┬─▶ tapRefM ─▶ bus
                                                    │   （一次反射：几何延迟）   └─▶ Panner(镜像位) ▶ tapRefS ▶ bus
                                                    └─▶ gW/gX/gY/gZ ──▶ W/X/Y/Z 四通道总线

FOA 解码（第一次切到该模式时才建）：
  W/X/Y/Z ──▶ 9 × (4 个解码增益 ▶ 求和 ▶ Panner(HRTF, 位于扬声器方向)) ──▶ tapFoa ──▶ bus

总线：
  bus ─┬─▶ dry ─────────────────┐
       └─▶ Convolver ▶ wet ─────┴─▶ master ▶ Compressor ▶ destination
```

- 四条支路常驻，切换模式只是把对应 `tap` 的增益拉上去/压下来（`updateVoices` 里带 0.16 的平滑系数），
  不会重建节点，所以切换时没有咔嗒声。
- 距离滤波在**分叉之前**，所以「单声道」也能听出远近（只有音量变化的远近是最弱的线索）。
- 反射有两条出口：`tapRefM`（单声道模式，不分方位）与 `tapRefS`（经镜像位置的 Panner）。
  这样"单声道"不会偷渡方向信息。
- 距离衰减用手写的 `1 / (1 + 0.5·max(0, d-1))`，与 Panner 的 `inverse`（refDistance 1、rolloff 0.5）保持一致，
  这样四种模式响度大致可比。反射用的 Panner 把 `rolloffFactor` 设成 **0**——它的距离规律由
  `refGain` 自己算，否则会被 Panner 再按 1/r 衰减一次，远距离的 D/R 反而下降。
- 混响 IR 是现算的：18 ms 预延迟 + 45 ms 建立 + 指数衰减噪声 `(1-p)^2.4`，**不含离散早期反射**
  （见第二节第 7 小节）；改 RT60 就重算并替换 `ConvolverNode.buffer`。
- 所有随时间变化的滤波器频率、增益、延迟都用 `setTargetAtTime`（时间常数 20–50 ms），
  拖动声源时不会出现拉链噪声或相位爆音。

## 七、一阶 Ambisonics 的编码与解码

这是「表示演进」的最后一站：单声道 → 立体声 → 双耳 → FOA。前三种是**直接渲染**，
FOA 不一样——它编码的是声场本身，必须按播放设备解码才能听。

### 1. 编码（AmbiX）

每条声源按方向写成四个分量：

```
W = 0.707 · s                             全向
X = s · cos(az) · cos(el)                 前后（前为正）
Y = -s · sin(az) · cos(el)                左右（左为正）
Z = s · sin(el)                           上下
```

四个分量各自汇入一条总线。单声源时这条流就是那个方向的平面波；多声源时是它们的线性叠加，
**声源之间的空间关系被保留在通道间的幅度与极性里**，这也是 FOA 只占 4 个通道却能表达声场的原因。

### 2. 解码（虚拟扬声器法）

9 个虚拟扬声器：8 个水平（45° 一档）+ 1 个顶置。每个扬声器的馈给是四通道的线性组合，
系数用与编码相同的实球谐基：

```
g_i = Σ_c B_c(d_i) · Y_c ,   B = [0.707, cos(az)cos(el), -sin(az)cos(el), sin(el)]
```

9 路分别用 HRTF 定位后相加，就得到双耳信号。这一步对应报告里说的「FOA 需按播放设备解码」——
耳机是其中一种播放设备。

- **归一化系数 1.50** 是实测出来的：9 路相干信号相加后与 HRTF 模式的平均能量差 <0.5 dB。
  理论推导给不出这个数，因为 HRTF 对各方向的增益不是常数。
- 虚拟扬声器的 Panner 把 `rolloffFactor` 设为 0，距离衰减由编码端自己乘（见下面第 4 条）。
- 9 个 HRTF 卷积器只在**第一次切到 FOA 模式**时才创建；没用到就不占 CPU。
  实测 FOA 模式下渲染仍是 60 fps。

### 3. 局限（这些是方法本身的，不是实现 bug）

- **空间分辨率低**：一阶 Ambisonics 只有 4 个通道，侧向定位明显弱于双耳 HRTF。
  实测同一位置（右前方 45°）的左右能量比：HRTF 8.0 dB，FOA 3.4 dB。
- **前后混淆更明显**：一阶球谐在前后方向上的差异很小。
- **ITD 略偏大**：解码后的实测 ITD 比设定值大约 60–125 µs（HRTF 模式是 50–90 µs），
  因为 9 个扬声器的 HRTF 叠加会带来额外的群延迟。

### 4. 一个实现上的坑

FOA 支路是从 `distShelf` 取的，也就是在 Panner **之前**。Panner 的距离衰减拿不到，
所以编码系数里必须自己乘上 `1/(1+0.5·max(0,d-1))`。否则 FOA 模式里远近只剩高频差异，
响度完全不随距离变化——这个 bug 在初版里真实存在过，是靠评测面板的读数发现的。

## 八、客观评测

对应报告里「客观指标 + 主观听评」的客观那一半。三个量都能在浏览器里实时算，不需要参考数据集。

### 1. ITD 误差

从**输出**的左右声道互相关实测时间差，与模型设定的值比较：

```
搜索 ±1 ms，找归一化互相关最大的滞后；
实测 ITD = -lag / fs；误差 = 实测 - 设定
```

实测（单声源，固定方位）：

| 方位 | 设定 ITD | HRTF 实测 / 误差 | FOA 实测 / 误差 |
|---|---|---|---|
| 正前 0° | 0 µs | 0 / 0 | 0 / 0 |
| 右前 45° | 377 µs | +426 / **+49** | +502 / +125 |
| 左前 45° | 377 µs | −425 / **−48** | −477 / −100 |
| 正右 90° | 650 µs | +560 / **−89** | +589 / −61 |
| 正后 180° | 0 µs | 0 / 0 | 0 / 0 |

**什么时候不出数**：多声源时"应该有"的 ITD 本身不唯一，互相关的峰位也不对应某一个声源；
信号太弱（相关峰 < 0.72）同理。这两种情况界面显示「多源」而不是给一个看着精确的错值。

**声源移动时读数会偏大**：测量窗 2048 样本（42 ms）加指数平滑，目标值却是即时计算的，
两者有时间差。观察数值时应让声源静止（把轨迹切到「静止」）。

### 2. FOA 角度误差

从 W/X/Y/Z 的**有功声强矢量**算方向，与设定的声源方向比较：

```
I = ( <W·X>, <W·Y>, <W·Z> )            在 2048 样本窗内累加，再做指数平滑
方向(世界系) = normalize(-I_y, I_z, -I_x)
角度误差 = acos( 单位矢量点积 )
```

用三维方向而不是方位角，是为了避开声源接近头顶时方位角发散的问题。

单声源实测：五个方位（0° / ±45° / 90° / 180°）的角度误差都在 **0.0–0.2°**。
这说明编码与解码在方向上是精确的——误差主要来自 ITD 与左右能量比，而不是方向。

### 3. 扩散度

```
扩散度 = 1 - |I| / E
```

单声源 ≈ 0；多个方向分散的声源同时发声时升高（实测「全景默认」6 声源约 0.3–0.7）。
它衡量的是「声场有多散」，与方向误差互补。

### 4. 为什么不做 FAD / CLAP / FSAD

这三个指标都需要**训练好的特征提取模型**（FAD 要 VGGish 类特征，CLAP 要音频-文本对比模型）与成对的
参考数据集。浏览器里既没有这些权重，也没有可比的真值，硬做一个近似只会得到看起来有数字、
实际没有意义的结论。报告里的这三项属于模型训练阶段的评测，不属于播放端能算的东西。
