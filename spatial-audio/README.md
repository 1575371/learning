# 空间音频实验室 · Spatial Audio Lab

一个可以直接在浏览器里打开的三维空间音频演示：把声音放进一个有地面、有高度、有混响的房间里，
拖动声源或自己画一条轨迹，实时听见它从哪个方向来、离你多远，并读出双耳定位线索 ITD / ILD。

纯前端、零依赖。犬吠与脚步用的是两段真实录音（内嵌成 base64，双击 `file://` 也能解码），
其余四个声源由 Web Audio 实时合成——所有声音都在浏览器里完成空间化。

---

## 复现范围

这份 demo 对应《空间音频合成研究》里的**表示链路**与**评测方法**两部分：

| 报告内容 | 本 demo | 状态 |
|---|---|---|
| 单声道 → 立体声 → 双耳 → FOA 的表示演进 | 五种空间化模式，可即时切换、可 A/B 轮转 | ✅ |
| 路线一「先有声音，再空间化」 | 实录/合成声源 → 距离滤波 → 空间化 → 混响 | ✅ |
| FOA 编码 + 按设备解码 | W/X/Y/Z 编码 + 9 扬声器双耳解码 | ✅ |
| 客观评测（ITD 误差、FOA 角度/扩散度）+ 主观听评 | 右下「评测」面板，实时计算 | ✅（FAD/CLAP/FSAD 除外） |
| 路线二「联合生成」 | — | ❌ 需训练扩散模型 |
| CSAVocoder / SwanSphere / SwanWeave | — | ❌ 需 GPU 训练与大规模数据 |

后三者的核心是「用神经网络生成或编辑波形」，浏览器端不可能训练。可行的工程组合是：
本地做空间化（本 demo 已覆盖），生成部分交给推理服务，前端推流播放。
逐页对照与未复现项的原因见 `docs/tech-notes.md` 第九节。

## 一、怎么打开

**直接双击 `index.html`**，用 Chrome / Edge / Firefox 的较新版本打开即可。不需要服务器、不需要安装依赖、不联网。

> 首次打开会看到「进入房间」遮罩，点一下「开始试听」。这是浏览器的自动播放策略要求的一次用户手势，不是故障。

需要 http:// 打开时（比如手机同局域网试听）：

```bash
npm start          # → http://127.0.0.1:8080/
npm run verify     # 交付前自检：文件完整、引用有效、语法、加载顺序、内嵌音频
```

两个脚本都不装任何依赖；不装 Node 也照样能双击 `index.html`。

戴耳机。用音箱外放，双耳线索（ITD / 头部遮蔽）基本听不出来，演示价值会丢掉大半。

## 五、坐标与参数约定

右手坐标系，与 Web Audio 的监听者坐标一致：

```
        -Z （正前方）
             ↑
  -X ← 听者 → +X      Y 轴向上（离地高度）
             ↓
        +Z （正后方）
```

- 单位为**米**，听者站在原点，耳平面高度 **1.55 m**，房间 9.2 × 9.2 × 3.2 m
- 声源的 `离地高度` 就是它在三维场景里的 y 值：0 表示放地上，2.3 表示挂在头顶上方
- `方位角` 以正前方为 0°，向右为正、向左为负，界面显示为「左 45.0°」这类文字
- `距离` 是声源到**双耳**的直线距离，不是到脚下的距离
- 直线轨迹的 A 是起点、B 是终点，`单程时长` 指 A→B 的时间（往返为一个完整周期）

## 六、技术实现要点

### 1. 三维视图（`view.js`）

没有引 three.js，也没有用 WebGL——场景只有几十个图元，用 Canvas 2D 手写透视投影反而更轻、文字更清晰，
而且不用打包、`file://` 直接能跑。

- 轨道相机：位置由 `yaw / pitch / dist` 决定，绕 `pivot` 旋转
- 投影：`screen = center + (v·right, v·up) / (v·forward) × focal`
- 拖拽：把鼠标位置反解成一条射线，与「当前高度所在的水平面」求交，得到世界坐标
- 深度：声源与听者按相机距离排序后依次绘制（画家算法）
- 标签：所有标签延后到一个独立图层绘制，做矩形避让，必要时用细线连回声源
- 取景：按房间 8 个角点的投影包围盒二分调整 `dist`，并把包围盒中心对到画布中心

### 2. 五种空间化方式

前四种每个声源在音频图里各带一条支路，用增益开关切换（不重建节点，避免爆音）；
第五种是场景级的编码-解码链路，单独一套。

| 模式 | 实现 | 听感特征 |
|---|---|---|
| 单声道 | 直连总线，只做距离衰减 | 没有方向 |
| 立体声 | `PannerNode(equalpower)` | 只有左右强弱差 |
| 双耳 · 模型 | 自建：每耳 = 增益 × 延时 × 低通 | ITD + ILD + 头部遮蔽，中间量可读数 |
| 双耳 · HRTF | `PannerNode('HRTF')`，浏览器内置实测 HRIR | 最自然，但拿不到中间量 |
| 一阶 Ambisonics | W/X/Y/Z 编码 + 9 扬声器双耳解码 | 声场感强、定位比双耳粗，见下面第 7 小节 |

### 3. 一阶 Ambisonics：真的能听

底部那四根 W/X/Y/Z 的条不只是可视化——它是一条真实的 FOA 链路。

**编码**：每个声源按方向写成 `W = 0.707s`、`X = s·cos(az)cos(el)`、`Y = -s·sin(az)cos(el)`、`Z = s·sin(el)`
（AmbiX 约定），四条支路汇入四条总线。多声源时叠加，声源之间的空间关系就编码在通道间的幅度与极性里。

**解码**：9 个虚拟扬声器（8 个水平 + 1 个顶置），每个扬声器的馈给是四通道的线性组合，
系数用与编码相同的实球谐基；9 路分别用 HRTF 定位后相加。这就是「按播放设备解码」在耳机上的那一支。

- 9 个 HRTF 卷积器只在第一次切到该模式时才建，不用就不占 CPU
- 电平与 HRTF 模式差 <0.5 dB（归一化系数是实测定的）
- **局限**：一阶只有 4 个通道，侧向定位明显弱于双耳——同一位置左右能量比 HRTF 8.0 dB、FOA 3.4 dB

### 4. 双耳线索

- ITD 用 Woodworth 球头近似：`τ = (a/c)·(θ + sinθ)`，a = 8.75 cm，c = 343 m/s，侧向 90° 时约 0.66 ms；
  这里的 θ 是**侧向角**（`asin(|x|/√(x²+z²))`，0–90°），正前与正后方都是 0
- ILD 侧向最大 9 dB，按 ±ILD/2 分给两耳，保证总响度大致不变
- 远耳高频遮蔽：低通截止频率随侧向角指数下降；再叠加随距离增加的高频衰减

### 5. 声音从哪来

**犬吠与脚步 = 真实录音**（`assets/audio/*.mp3`，以 base64 内嵌在 `assets/js/samples.js` 里）。

- 页面加载时就用 `OfflineAudioContext.decodeAudioData()` 解码好，点「开始试听」时已经就绪
- 犬吠原素材 1.62 s / 两声，引擎把它拼成 **6.37 s 的循环**：三组之间留 0 / 0.35 / 0.9 s 的不同间隔，
  并用 ±3% 的变速做出音高微差（`buildBarkLoop()`），循环起来是「汪 汪 …… 汪 汪」而不是每 1.6 s 精确重复
- 脚步原素材 5.25 s / 八步，本身含一次自然停顿，直接循环使用，步间隔 0.59 s 与录音一致
- 两段录音都近乎单声道、底噪很低（−54 dB / −40 dB），混入房间混响不会「二次混响」

**其余四个声源仍是实时合成的**：铃声（五个非整数倍分音）、雨声（带通噪声床 + 随机水滴）、
拨弦（Karplus-Strong 弦模型）、号角（奇次谐波方波堆）。

`synth.js` 里保留了犬吠与脚步的**合成实现**，作为录音解码失败时的自动回退——那个版本用的是
声源—滤波器模型（声门脉冲 + 时变共振峰 + 送气噪声），删掉 `samples.js` 也能正常出声，只是真实度差一档。

### 6. 房间混响

`ConvolverNode` + 程序化脉冲响应：18 ms 预延迟 + 45 ms 建立 + 指数衰减噪声。
RT60 变化时实时重算并替换。

> IR 里**故意不放离散早期反射**。早期反射改由每条声源自己的镜像支路提供（带真实方向），
> 总线再放一遍就是重复计入，听感会"糊"和"厚"。

### 7. 距离感知：空气吸收 + 一次反射

这是本项目距离感的主要来源，两条线索同向叠加。

**① 空气吸收**（放在四种模式分叉之前，所以单声道也有效）

```
截止 = 20000 · exp(-0.17 · max(0, d-0.8) · absorb)     // 低通，Q 0.4
高架 = min(1.8 · max(0, d-0.8) · absorb, 14)           // 3.2 kHz 以上下压
```

Q 取 0.4 而不是默认的 1，是为了避开截止频率附近的隆起——那正是"刺耳"的来源；
高架只减不加，近处不 boost。

**② 一次反射**（镜像声源法）

把声源对最近的墙做镜像，虚声源的方向就是反射入射方向，延迟按路径差算：
`Δt = (|S′-L| − |S−L|) / c`，实测在 1–21 ms 之间随位置变化。
反射再过一道低通（墙面吸声），并且**衰减比直达慢**，于是 D/R 随距离上升。

| 参数 | 范围 | 默认 | 作用 |
|---|---|---|---|
| 空气吸收 | 0 – 200% | 100% | 高频随距离衰减的强度。**0 = 远近只差音量**（对照用），200 = 远处非常闷 |
| 一次反射 强度 | 0 – 150% | 80% | 直达/反射比。0 = 纯直达声，150 = 明显更"湿" |
| 反射延迟 | 0.4 – 2.5× | 1.0× | 几何延迟的倍率。调大像更大的空间（1.0× ≈ 10–20 ms） |
| 墙面吸声 | 0 – 100% | 50% | 反射的高频损失。0 = 硬墙（反射更亮），100 = 软墙（只剩低频） |

底部指标条的 **直达/反射** 就是当前选中声源的 D/R（dB），参数块折叠时也实时更新。

**怎么听出效果**：选「走廊脚步」，让声源从 4 m 走到 0.9 m。走近时高频截止从 ~11 kHz
回到 20 kHz、D/R 从 −6 dB 掉到 −15 dB，两个线索一起变化，比只改音量明显得多。
把「空气吸收」拉到 0 再听一遍，就是这个演示没有这两条线索时的样子。

### 8. 客观评测（`#rateBlock`）

右下角「评测 · 客观 + 主观」里除了三项主观打分，还有三个**从输出实测**的客观量：

| 指标 | 怎么算 | 实测值 |
|---|---|---|
| ITD 误差 | 左右声道互相关找峰位，与设定值比较 | HRTF 模式 ±49 µs 以内，FOA ±125 µs 以内 |
| FOA 角度误差 | W/X/Y/Z 的有功声强矢量 vs 设定方向 | 单声源 0.0–0.2° |
| 扩散度 | `1 - |I|/E` | 单声源 0，六个声源分散时 0.3–0.7 |

**多源时显示「多源」而不是数字**：这时"应该有"的 ITD 与方位本身不唯一，互相关峰位也不对应某一个声源，
与其给一个看着精确的错值，不如不出数。想看具体数值就切到「擦身而过」或「走廊脚步」。

FAD / CLAP / FSAD 没有做——它们需要训练好的特征模型与成对参考数据，浏览器里既没有权重也没有真值。

## 七、已知取舍与限制

1. **「双耳 · 模型」是简化模型**，不是实测 HRIR。它的价值在于中间量可解释、可读数；追求音质请用 HRTF 模式。
2. **只算了一次镜面反射**。真实房间有来自各个方向的多次反射与扩散场，这里用「一次镜像反射 +
   总线混响」近似。副作用是：贴着墙的声源几何延迟可能不足 1 ms，会与直达声形成梳状滤波，
   所以延迟被抬到 3.5 ms 的下限——这会让墙角声源的房间听起来比实际稍大。
   同理，反射声本身用的是直达声的距离滤波（不再额外按反射路径滤波），够用但不严格。
3. **FOA 只做了编码可视化**。底部 W/X/Y/Z 是按 AmbiX 约定实时算出的编码系数，没有做四通道渲染与解码播放——
   那需要按播放设备（双耳 / 扬声器阵列）分别设计解码器。
4. **只有犬吠和脚步用了真实录音**。另外四个声源仍是合成的，音色和真录音有差距；
   如果要整体都用实录，按下一节的办法替换即可。
5. **D/R 随距离的变化依赖声源位置**。在开阔处随距离单调下降（这正是要的线索）；
   但如果声源本身贴近墙面，反射路径变短，D/R 会偏高——这是物理正确的，不是 bug。
6. **一阶 Ambisonics 的空间分辨率有限**。只有 4 个通道，侧向与前后分辨都弱于双耳 HRTF；
   解码后的实测 ITD 也比设定值偏大 60–125 µs。这是格式本身的限制，不是实现问题。
7. 音频图为 6 个声源 × 5 条支路 + 距离滤波 + 反射链；FOA 解码另有 9 个 HRTF 卷积器（按需创建）。
   实测 FOA 模式下渲染仍是 60 fps；低端设备若出现爆音，可降低主音量或减少同时启用的声源。

## 八、换成自己的录音

犬吠和脚步走的是**内嵌录音**这条路，换素材分两步：

**1）替换原始素材**：把 `assets/audio/dog_barking.mp3`、`footsteps.mp3` 换成你的录音。

**2）重新生成内嵌数据**（file:// 下 fetch 本地文件会被 CORS 拦，所以必须内嵌成 base64）：

```bash
node -e "const fs=require('fs');
const b=p=>'data:audio/mpeg;base64,'+fs.readFileSync(p).toString('base64');
fs.writeFileSync('assets/js/samples.js',
  'window.SALab=window.SALab||{};window.SALab.SAMPLE_MP3={'+
  'bark:\''+b('assets/audio/dog_barking.mp3')+'\','+
  'steps:\''+b('assets/audio/footsteps.mp3')+'\'};');"
```

> 键名必须叫 `bark` 和 `steps`（与 `core.js` 里 `DEFS` 的 `sound` 字段一致）。

**录音要求**：单声道或立体声都行（会自动混单声道）、48 kHz 最好、尽量是**干声**——
带房间混响的素材会与本项目的卷积混响叠加，听起来发糊。犬吠素材最好是一两声一组的干净吠叫，
引擎会自动拼成循环；脚步素材最好包含连续的几步，步间隔会被原样保留。

**想让某一段录音不参与循环、只当作单次触发**：目前引擎是按循环用的，需要改
`engine.js` 里 `bs.loop = true` 那一行，改成一次性播放并按事件调度。

## 九、原来的做法：全合成（已作为回退）

`synth.js` 里仍然保留犬吠与脚步的合成实现。删掉 `assets/js/samples.js`（或解码失败）时，
引擎会自动回退到它们，页面照常出声：

```js
const bs = ctx.createBufferSource();
bs.buffer = audio.buffers[s.def.sound];   // 有录音用录音，没有就用合成
```

只要把这一行换成 `fetch()` + `decodeAudioData()` 得到的缓冲区，后面的空间化链路完全不用改。
注意：缓冲区需要是**单声道**，空间方位由后面的 Panner / 双耳链路决定。

## 十、常见问题

**打开后没有声音？**
先确认点了「进入房间 → 开始试听」；再看系统输出设备是否选对；最后检查标签页是否被静音。

**听不出方向？**
戴耳机。另外「单声道」模式本来就没有方向，确认左侧选中的是「双耳 · HRTF」或「双耳 · 模型」。

**拖不动声源？**
只有未静音（ON）的声源才会出现在场景里，也才能拖动。先点一下声源球把它选中，圆点外会出现虚线环。

**加点加到了不想放的地方？**
`撤销` 删最后一个点，或直接双击那个点删掉。`Esc` 退出加点模式。

**视角转到奇怪的角度了？**
点 `斜视` 复位，镜头会自动重新取景。
